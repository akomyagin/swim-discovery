# swim-discovery — POST_MVP_PLAN

Идеи после MVP. Ничего из этого не входит в v1 — MVP сознательно ограничен
localhost-эмуляцией без безопасности и без прикладных метаданных, чтобы держать
фокус на самом gossip/failure-detection ядре.

## Сеть за пределами localhost

- **Реальная многомашинная сеть.** Вынести узлы на разные хосты/контейнеры,
  проверить детекцию отказов на настоящей сети (реальные RTT, MTU, потеря
  пакетов). Потребует конфигурации внешних адресов, а не только `127.0.0.1:*`.
- **NAT / несколько интерфейсов.** Разделить bind-адрес и advertise-адрес
  (как у Serf/Consul), чтобы узел за NAT анонсировал достижимый адрес.
- **TCP fallback для больших payload-ов / антиэнтропии.** SWIM-полный
  push-pull sync членства по TCP при присоединении, когда UDP-датаграмма мала.

## Безопасность между узлами

- **Шифрование/аутентификация трафика.** Симметричный ключ кластера
  (AEAD поверх датаграмм) или mTLS для TCP-канала, чтобы чужой узел не мог
  вступить в кластер или подделать слухи. В v1 сознательно вырезано.
- **Защита от подделки слухов.** Подписи apdate-ов, чтобы узел не мог
  фальсифицировать `Dead` про другого.

## Прикладной discovery в стиле Consul/Serf

- **Произвольные метаданные узла (теги).** Каждый узел несёт key/value-теги
  (роль, версия, зона) и список сервисов; распространяются тем же gossip-ом.
- **Запросы по членству.** «Все узлы с тегом `role=api` и статусом alive» —
  примитив service discovery поверх membership-списка.
- **User events / query-broadcast** в стиле Serf: рассылка произвольных событий
  по gossip-у.
- **Health checks прикладного уровня** сверх L1 failure detection (HTTP/TCP
  проба сервиса, а не только живость процесса).

## Протокол и наблюдаемость

- **Компактный бинарный wire-формат** вместо JSON (меньше датаграммы,
  ближе к реальным реализациям).
- **Lifeguard-улучшения SWIM** (адаптивные таймауты подозрения по локальной
  «здоровости» узла) для снижения false positives под нагрузкой.
- **Метрики/трейсинг сходимости** — экспорт времени конвергенции, числа
  false positive, gossip-трафика; дашборд для наблюдения кластера.
- **Persistent membership snapshot** — восстановление списка соседей после
  рестарта узла (как `serf` snapshot).
