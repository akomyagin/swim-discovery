# swim-discovery

Учебная реализация **service discovery на gossip-протоколе** (мини-Serf /
мини-Consul membership) на Go. Узлы находят друг друга и детектят отказы через
SWIM-подобный протокол — **без центрального координатора**. Каждый узел держит
собственный, со временем сходящийся список членов кластера (кто жив, под
подозрением, мёртв).

Pet-проект соло-разработчика: цель — техническая сложность и обучение, не
продукт. Только стандартная библиотека Go, без внешних зависимостей и Docker —
кластер эмулируется несколькими процессами на localhost.

## Почему это интересно

Наивный failure detector «пингуй всех напрямую» даёт **false positives** при
потере пакетов: потерялся *твой* пакет к узлу — и ты ошибочно счёл живой узел
мёртвым. SWIM лечит это **indirect probing**: не получив ответа, узел просит K
случайных посредников пропинговать цель от своего имени. Честно оттестировать
это тяжелее, чем кажется — нужен детерминированный симулятор сети с управляемой
потерей пакетов.

## Сборка

```bash
go build ./...   # сборка
go vet ./...     # статический анализ
go test ./...    # тесты (юниты + интеграция на fake-транспорте, без реальной сети)
```

## Раскладка

| Путь | Содержимое |
|---|---|
| `internal/member/` | модель узла (`Member`, `State`) + membership-список с merge по incarnation |
| `internal/transport/` | порт `Transport` + UDP-адаптер (+ fake-симулятор сети, Этап 5) |
| `internal/protocol/` | wire-сообщения SWIM (Ping/Ack/PingReq + gossip Update), Encode/Decode |
| `cmd/swim-discovery/` | тонкий CLI: запуск узла, наблюдение за кластером |
